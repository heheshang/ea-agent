# 触达复盘分析

## 适用场景
用户要求「复盘某活动触达」「触达成功率/失败分析」「活动投放效果」时，按本技能流程执行。

## 执行步骤

1. **锁定活动**：先调用 `getCampaign` 确认活动配置（触发规则/灰度），再调用 `queryDelivery`（参数 `campaign_id` 必填，可加 `limit`）拉取该活动触达流水。

2. **汇总统计**：基于 `queryDelivery` 返回的 `rows` 计算：
   - 总触达数、成功数、失败数、成功率（成功 = `status == 'SUCCESS'`）
   - 平均耗时（`duration_ms` 求均值，量级过大转秒）
   - 失败原因分布（按 `error`/`remark` 字段归类：通道拒绝、超时、退订等）

3. **交叉分析**（可选）：触达表现异常时调用 `queryEvents`（客户事件流）与 `callFunction`（咨询函数）核对客户画像上下文；不建议扩大查询范围。

4. **输出**：中文简洁结论 + 表格化统计（三行内）+ 1~2 条可执行优化建议（如冷却窗、灰度比例、通道切换）。不要输出原始 JSON 全量。

## 注意事项
- 只使用工具返回的数据，不臆测缺失字段；`status` 缺失时标记为「未知」并注明。
- 成功率低于 60% 时必须在结论中明确标注，并给出至少一条可执行建议。
